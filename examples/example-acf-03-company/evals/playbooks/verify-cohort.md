# Notebook verification exercise

The notebook-provenance seed is deliberately draft. Its source pointer is fictional
and unavailable; do not report a verification pass or fabricate a source hash.
Provide a real source notebook outside this context repo, import/review its method,
and agree on pinned inputs, window bindings, output keys and tolerances with a human.
Rerun it in a fresh read-only session. In a separate answering-agent context, use
only the reviewed method, metrics and the same bindings to derive and execute the
answer. Compare keyed rows and disclosures. An empty cohort yields null, and the
fixture follow-up is partial. Save executed notebooks/code/rows privately under
`.nodal/` or `evals/runs/`, then ask the human to confirm the snapshot comparison.
Only that review can replace the fictional pointer and promote the notebook seed.
Python-only verification requires no invented SQL sidecar.
